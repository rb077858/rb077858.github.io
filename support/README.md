# chat.reembir.com — צ׳אט שירות לקוחות

מערכת צ׳אט מלאה לאתרים של reem.bi: ווידג׳ט שמוטמע בשורה אחת בכל אתר, ומוקד נציגים עם ניהול צוות, היסטוריה, דוחות והתראות.
רצה בחינם על **Cloudflare Workers + Durable Objects** (עם מסד SQLite מובנה, בלי מסד נתונים נפרד להקים), והמיילים יוצאים דרך **Resend** — אותו חשבון של login.reembir.com.

```html
<script src="https://chat.reembir.com/widget.js" data-site="timlul" async></script>
```

## עיצוב הצ׳אט לכל אתר

הצ׳אט נטען מכתובת אחת, אבל כל אתר יכול לתת לו מראה משלו: צורה, צבעים, גופן, כפתור פתיחה, מיקום. הכי קל: **chat.reembir.com/theme**. משנים שם, רואים את הצ׳אט משתנה בפינת המסך, ומעתיקים את הקוד.

הקוד הוא אותה שורת script עם עוד כמה attributes. רק מה שמשתנה צריך להופיע:
```html
<script src="https://chat.reembir.com/widget.js" async
  data-site="timlul"
  data-preset="sharp" data-brand="#1a1814" data-highlight="#f5d63f"
  data-launcher="square" data-launcher-icon="wave"></script>
```

- **צורה:** `data-preset` = `soft` (ברירת המחדל), `flat` (צבע אחד, בלי עיטורים) או `sharp` (מרובע, עם מסגרת, בלי צללים). אפשר לשנות כל פרט מעליה.
- **צבעים:** `data-brand`, `data-accent`, `data-highlight`, `data-ink`, `data-bg`, `data-card`, `data-line`, `data-muted`. צבע טקסט על רקע צבעוני נבחר לבד כך שיהיה קריא.
- **פינות ועומק:** `data-radius` (0 עד 40), `data-border`, `data-shadow` (`soft` / `none` / `hard` או `box-shadow` של CSS), `data-gradient`, `data-deco`.
- **גופן:** `data-font`, `data-font-head`, `data-font-url` (הקישור ל-Google Fonts, אם האתר לא טוען אותו כבר).
- **כפתור:** `data-launcher` (`round` / `pill` / `square`), `data-launcher-icon`, `data-launcher-label`, `data-size`.
- **מקום וגודל:** `data-position`, `data-width`, `data-height`, `data-offset-x`, `data-offset-y`, `data-z`.
- **בלי לגעת ב-HTML:** משתני CSS באתר (`:root { --reemchat-brand: #1a1814; }`), או `ReemChat.theme({ brand: '#1a1814' })` בקוד, בזמן שהדף רץ.

סדר העדיפויות, מהנמוך לגבוה: הגדרות הדשבורד של הצ׳אט (צבעים, מיקום) ← משתני CSS ← attributes ← `ReemChat.theme()`. אתר שלא הגדיר כלום נראה כמו קודם.

## כמה אתרים בצ׳אט אחד
- **מאיזה אתר:** `data-site` = המזהה של האתר ב-reem.bi (למשל `timlul`). בלעדיו האתר מזוהה לפי הכתובת של הדף. בכל שיחה יש תג עם שם האתר, ובתיבת השיחות יש סינון לפי אתר (כשיש יותר מאחד).
- **חשבון מאומת:** אתר שמשתמש בהתחברות של reem.bi קורא אחרי ההתחברות ל-`ReemChat.identify({ token: auth.getToken(), name, email })`. הצ׳אט בודק את הטוקן מול login.reembir.com, והנציג רואה "חשבון reem.bi ✓ מאומת" עם המייל. כל הפעולות על החשבון הולכות אליו בלי לחפש.

## מה יש במערכת

**הווידג׳ט באתר** (`public/widget.js`)
- כפתור צף מונפש עם מונה הודעות שלא נקראו, ובועת ברכה קופצת
- טופס פתיחה (שם / מייל / טלפון / נושא) — כל שדה: חובה, רשות, או לא לשאול
- זמן אמת: הודעות, "מקליד/ה…", אישורי קריאה ✓, הצטרפות והעברת נציג
- קבצים ותמונות, אימוג׳י, קישורים לחיצים, צלילים והבהוב בכותרת הלשונית
- כשאין נציגים זמינים / מחוץ לשעות הפעילות: טופס השארת הודעה שנשלח לצוות במייל
- דירוג 1-5 כוכבים בסוף השיחה, ושליחת תמליל השיחה למייל
- עברית ואנגלית (RTL/LTR אוטומטי), מסך מלא בנייד, מצב כהה של האתר לא שובר אותו (Shadow DOM)
- השיחה נשמרת בין דפים וביקורים; `?chat=open` בקישור פותח את הצ׳אט

**מוקד הנציגים** (`/admin`)
- **תיבת שיחות** בשלוש עמודות: שלי / ממתינות / כל הפתוחות / סגורות, חיפוש בתוכן ההודעות
- **Whisper — הערות פנימיות** בתוך שיחה (הלקוח לא רואה), עם **@תיוג** נציג שמקבל התראה מיידית (ומייל אם הוא לא מחובר)
- **תצוגה מקדימה** של מה שהלקוח מקליד, עוד לפני שלחץ "שליחה"
- מי עוד צופה בשיחה ומי מקליד — כדי ששני נציגים לא יענו יחד
- שיוך והעברת שיחות בין נציגים, סגירה ופתיחה מחדש, תגיות, הערות על הלקוח, חסימת מבקר
- כרטיס לקוח: פרטים (עריכה במקום), מיקום, דפדפן, מסלול הדפים באתר, שיחות קודמות
- **תשובות מוכנות** — מקלידים `/` בחלון השיחה, עם משתנים `{name}` `{agent}`
- **מבקרים באתר עכשיו** — מי נמצא איפה, ופתיחת שיחה יזומה איתם
- **היסטוריה** עם סינון (נציג, תגית, דירוג, תאריכים) וייצוא ל-CSV
- **דוחות**: כמות שיחות, אחוז מענה, זמן מענה ראשון, שביעות רצון, מפת עומסים לפי יום ושעה, ביצועי נציגים
- **ניהול צוות**: הזמנה במייל, הרשאות מנהל/נציג, מקסימום שיחות במקביל, השבתה
- **הגדרות**: צבעים וטקסטים עם תצוגה מקדימה חיה, שעות פעילות, שיבוץ ידני או אוטומטי (round-robin), אתרים מורשים ועוד
- סטטוס זמין / לא זמין, צלילים, התראות דסקטופ, מצב כהה

**תשלומים ושדרוגים מתוך הצ׳אט** (דרך login.reembir.com)
- **בקשת תשלום בשיחה** — כפתור 💳 ליד שדה הכתיבה: סכום, מטבע, תיאור, תוקף (עד תאריך / עד סיום השיחה / ללא), ולמי (לפי מייל, או חשבון reem.bi מסוים). הלקוח מקבל בצ׳אט כרטיס עם הסכום וכפתור לתשלום מאובטח; אפשר לשלוח גם במייל. הכרטיס מתעדכן לבד ל"שולם" / "בוטל" / "פג תוקף", והנציג מקבל התראה כשמשלמים
- **שדרוג אוטומטי אחרי תשלום** — בוחרים חשבון ← אתר ← תוכנית (+ מספר ימים), וברגע שהלקוח משלם החשבון משודרג לבד
- **שדרוג ידני** — מכרטיס הלקוח: "שדרוג חשבון" (חיפוש חשבון, אתר, תוכנית, ימים)
- כדי לשלם הלקוח **חייב להיות מחובר** לחשבון reem.bi; התנתקות (גם באתר אחר) עוצרת את התשלום

**פעולות על החשבון של הלקוח** (כפתור **🎁 פעולות** ליד שדה הכתיבה, וגם בכרטיס הלקוח)
- **חבילה לרכישה:** כרטיס תשלום במחיר החבילה. אחרי התשלום החבילה נוספת לחשבון לבד (כמו קנייה באתר)
- **מתנה:** למשל 30 דקות, בחינם, לחשבון באתר. הלקוח מקבל הודעה בצ׳אט, והמתנה מופיעה בדשבורד של reem.bi בדף המשתמש ("מתנה מנציג בצ׳אט")
- **קופון אישי:** הנחה, חודשים חינם או תוכנית במתנה. קוד לשימוש אחד, בתוקף 30 יום, שנשלח ללקוח עם קישור שמחיל אותו באתר

**הרשאות לנציגים** (מנהלים יכולים הכול)
- בעמוד **צוות ← עריכה**: בקשות תשלום · שליחת חבילות · מתנות ללקוח · קופונים אישיים · שדרוג תוכניות · שליטה בתרגום. לכל הרשאה: בכל השיחות או רק בשיחות שמשויכות לנציג, ועד תאריך (או ללא הגבלה)
- **ובפירוט:** באילו אתרים (חבילות, מתנות, קופונים, שדרוגים) · לתשלומים: סכום ותוקף מקסימליים · למתנות: כמה לכל היותר בכל מתנה · לקופונים: אילו סוגים, אחוז הנחה מקסימלי וחודשים לכל היותר · לשדרוגים: אילו תוכניות וכמה ימים לכל היותר
- **הרשאה זמנית לשיחה אחת** — מתפריט השיחה ← "הרשאות זמניות לשיחה הזו". מתבטלת אוטומטית כשהשיחה נסגרת

**נציגי AI** (צוות ← 🤖 נציג AI חדש)
- נציג AI הוא נציג בצוות שעונה ללקוחות לבד. מגדירים אותו כמו כל נציג (שם, תפקיד, מקסימום שיחות, צבע, **הרשאות**), ועוד: **שפה** אחת ולתמיד, **שעות פעילות** (אפשר לפי יום, אזור זמן, וגם חצות), **הוראות וידע** (מה הוא יודע ואיך הוא מדבר), ו**מתי הוא לוקח שיחות**: תמיד כמו כל נציג, או רק כשאין נציג אנושי פנוי. אפשר לפתוח כמה נציגי AI שונים. אין לו אימייל או סיסמה והוא לא נכנס למערכת.
- הוא עובד עם **אותו מפתח Gemini של התרגום** (הגדרות ← תרגום AI, או `GEMINI_API_KEY`). בלי מפתח הוא מסומן "חסר מפתח" ולא פעיל.
- הוא זמין לפי השעות שלו, בלי קשר לשעות הפעילות של הצוות. כשהוא פעיל, הווידג'ט מציג "זמינים" גם כשאף נציג אנושי לא מחובר. גם עם שיבוץ ידני, נציג AI לוקח שיחה חדשה בעצמו.
- הוא כותב רק בשפה שנקבעה לו. אם הלקוח כותב בשפה אחרת והתרגום האוטומטי פעיל, התרגום מעביר בין השפות כרגיל (והוא קורא את הלקוח בשפה שלו).
- **העברה לנציג אנושי:** כשהלקוח מבקש אדם, כשהוא כועס, כשהנציג לא יודע או לא מצליח, או כשהוא מחוץ לשעות. השיחה חוזרת לתור (או לנציג אנושי, בשיבוץ אוטומטי), הצוות מקבל התראה, והנציג לא לוקח אותה בחזרה. מי שמשייך אליו את השיחה שוב מחזיר אותו לענות.
- **מה שלא מופעל, הנציג מעביר לנציג אנושי.** הוא לא שואל את הלקוח אם להעביר: הוא אומר שהוא מעביר, ומעביר. ובנציג שמוגדר "לא לציין" הוא לא אומר שזה נציג אנושי או "אדם אמיתי", אלא שהשיחה עוברת לאחד מהצוות. כשמחליפים נציג ל"לא לציין", תפקיד שהיה ברירת המחדל ("נציג AI", "עוזרת וירטואלית") נמחק.
- **מה הנציג יודע על הלקוח:** אם הלקוח מחובר לחשבון reem.bi (מאומת), הנציג רואה בכל תשובה את הנתונים מהמערכת: באיזו תוכנית הוא בכל אתר ועד מתי, המנוי (סטטוס, מחיר, עד מתי שולם), התשלומים האחרונים (כולל כשלים), מתנות שקיבל, האם המייל והטלפון מאומתים, מתי הצטרף ונכנס לאחרונה, בקשות התשלום בשיחה הזו והסטטוס שלהן, ושיחות קודמות. לקוח לא מחובר: הנציג יודע שאין לו גישה לנתונים, ומבקש להתחבר אם צריך. הנתונים מגיעים מ-login.reembir.com (נקודת `GET /api/service/users`).
- **הנציג לא רק שאלה-תשובה:** אם הוא אומר שהוא בודק, הוא בודק באמת, וכשהוא מסיים הוא כותב ללקוח הודעה חדשה עם מה שמצא. יש לו שתי דרכים:
  - **בדיקה (`look_up`):** הוא כותב משפט אחד ("רגע, אני בודקת בחשבון שלך"), המערכת קוראת את החשבון מחדש (בלי זיכרון) ושואלת את מערכת התשלומים על בקשות תשלום פתוחות בשיחה, והנציג נקרא שוב עם התוצאה וכותב ללקוח מה שמצא.
  - **שאלה לצוות (`ask_team`):** הוא כותב **הערה פנימית** לצוות (או למי שבחר בשמו), שהלקוח לא רואה. הוא אומר ללקוח שהוא שאל, ומחכה. כשנציג אנושי עונה בהערה פנימית בשיחה, הנציג נקרא שוב, קורא את התשובה וכותב ללקוח. אם אף אחד לא ענה תוך X דקות (מוגדר לכל נציג, ברירת מחדל 10), הוא אומר ללקוח שהשיחה עוברת לצוות ומעביר אותה. הצוות מקבל התראה על השאלה (ומייל, אם אף נציג לא מחובר).
  - הנחיה קבועה אליו: אסור להגיד "אני בודק" בלי לבצע אחת מהשתיים.
- **שאלה לעמית (לכל נציג, אנושי או AI):** אפשר לשאול עמית שאלה על שיחה **בלי להעביר לו אותה**. נציג אנושי: כפתור **?** בשורת הכתיבה ← בוחרים עמית (או כל הצוות) וכותבים. השאלה נכתבת בשיחה ככרטיס "❓ שאלה" (הערה פנימית, הלקוח לא רואה), והעמית מקבל התראה (ומייל אם אינו מחובר). העמית עונה בכרטיס, השאלה מסומנת "נענתה", והשואל מקבל התראה. השיחה נשארת אצל מי שהיא הייתה. רק מי ששאלו אותו (או מנהל) יכול לענות. נציג AI שואל באותה דרך (`ask_team`), מחכה, וכשעונים לו הוא כותב ללקוח. בנציג AI אפשר לכבות את זה ("מותר לנציג לשאול עמית"), ואז הוא לא שואל. כשמותר, ההנחיה אליו היא לשאול קודם, ולהעביר את השיחה רק אם התשובה מראה שאדם צריך לקחת אותה.
- **הודעות פנימיות:** הנציג קורא את ההערות הפנימיות (Whisper) שהצוות כתב בשיחה, ואת מה שהצוות עשה (מתנה, שדרוג, העברה), ומתחשב בהן. הלקוח לא רואה אותן והנציג לא מצטט אותן. ההצעות שהוא עצמו שלח לאישור לא נחשבות הערות.
- **סיום שיחה:** אפשר לאפשר לנציג לסיים שיחה כשהשאלה נענתה והלקוח אמר שהוא סיים או נפרד. הלקוח מקבל כרגיל את בקשת הדירוג, ונציג אנושי יכול לפתוח את השיחה מחדש. הוא לא סוגר כשיש הצעה שממתינה לאישור, וגם לא כשהוא מעביר את השיחה. הוא מונחה לסגור כשהלקוח סיים, ובנוסף: הודעה של לקוח שהיא רק תודה או פרידה ("תודה רבה", "זה הכל", "ביי") סוגרת את השיחה גם אם המודל שכח.
- **מין:** בכל נציג AI בוחרים זכר או נקבה, והוא מדבר על עצמו בהתאם (בעברית, ערבית ושפות עם לשון זכר ונקבה). גם הודעות המערכת בדשבורד ("העבירה את השיחה...") נכתבות לפי המין.
- **האם הלקוח יידע שזה עוזר וירטואלי:** בכל נציג בוחרים. "כן": הוא מציג את עצמו כעוזר וירטואלי בהודעה הראשונה, ומופיע "AI" ליד שמו (ובתפקיד, אם לא נכתב אחר, "עוזרת/עוזר וירטואלי"). "לא לציין": הוא לא מזכיר זאת ואין תג ללקוח, אבל אם לקוח שואל אותו ישירות אם הוא אדם או בוט, הוא עונה בכנות. הוא אף פעם לא יטען שהוא אדם. בדשבורד הצוות תמיד רואה "AI". במקומות מסוימים החוק מחייב לגלות ללקוח שהוא מדבר עם בינה מלאכותית (למשל באיחוד האירופי).
- נציג אנושי שלוקח שיחה עוצר אותו מיד.
- **הרשאות:** אפשר לתת לו כמו לכל נציג. אם הגדרתם, הוא משתמש ב**בקשות תשלום, מתנות וקופונים אישיים** (ראו למטה). שאר ההרשאות (חבילות, שדרוגים) נשמרות, אבל הוא לא מפעיל אותן בעצמו.
- **מה הנציג יכול לעשות בחשבון הלקוח:** מתנה, קופון אישי, בקשת תשלום, **שדרוג תוכנית** (נותן את התוכנית לחשבון ליותר ימים, בתוך המגבלות של הרשאת השדרוג) ו**חבילה** (בקשת תשלום על חבילה, שנוספת אחרי התשלום). לכל נציג AI בוחרים בנפרד לכל אחד מהחמישה: **כבוי**, **באישור נציג אנושי** או **אוטומטי**. זה עובד רק אם יש לנציג ההרשאה המתאימה, ובתוך המגבלות שלה (אתרים, סכום מקסימלי, סוגי קופון). מתנה דורשת לקוח מחובר לחשבון reem.bi.
  - **אוטומטי חכם (מתנה, קופון, שדרוג):** אלה נותנים משהו בחינם, ולכן הם מותרים רק כפיצוי על **בעיה אמיתית שלכם שמוצגת בשיחה**, ולא כי הלקוח ביקש. לקוח שמבקש לא מקבל: הנציג שואל מה בדיוק קרה (הודעת שגיאה, מתי, מה עשה), ואם אין בעיה הוא מסביר בנימוס שאי אפשר ועוזר בבעיה עצמה. בנוסף, בקוד (לא רק בהנחיה):
    - **תיעוד חובה:** הנציג צריך לכתוב מה הבעיה ומה בשיחה מראה אותה (בלי זה, שום דבר לא נעשה).
    - **מספיק פרטים:** הלקוח צריך לכתוב לפחות X הודעות (ברירת מחדל 3, אפשר לשנות) לפני שמתחילים לשקול הטבה.
    - **בודק עצמאי:** כל הצעה כזו עוברת קריאה נוספת של מודל נפרד, "בודק" חשדן, שקורא את כל השיחה, את התיעוד ואת **מדיניות הפיצוי שכתבתם בטופס** ומחליט. בלי "כן" ברור, זה לא. אם הבודק לא זמין, זה לא מתבצע.
    - **נרשם בשיחה:** אם נתן, הבעיה, הראיה והחלטת הבודק נרשמות בשיחה (הערת מערכת, וגם בכרטיס האישור במצב "באישור"). אם נדחה, גם הדחייה והסיבה נרשמות, והצוות רואה.
    - הבודק והנציג מבוססים על השיחה בלבד: הם לא בודקים לוגים של האתר עצמו, ולכן "הראיה" היא מה שהלקוח מתאר. להטבות גדולות מומלץ "באישור נציג אנושי".
  - לקוח שמבקש לא מקבל אוטומטית: הנציג שוקל לפי ההוראות שכתבתם ומה שנאמר בשיחה, והמודל מונחה לא להבטיח מראש ולא להיכנע ללחץ.
  - **באישור נציג אנושי:** ההצעה מופיעה בשיחה ככרטיס (🤖 הצעה לאישור) עם אישור ודחייה, רק לצוות. הלקוח מקבל רק אחרי שנציג **עם ההרשאה** אישר, והמגבלות שלו חלות. הנציג אומר ללקוח שביקש מעמית לאשר.
  - **אוטומטי:** הנציג נותן בעצמו, בתוך המגבלות של ההרשאה שלו.
  - **בקשת תשלום** היא כרטיס עם קישור תשלום בצ'אט (דרך login.reembir.com): הלקוח משלם בעצמו, אין חיוב אוטומטי. הסכום מוגבל לסכום המקסימלי שבהרשאת "בקשות תשלום" של הנציג, ונדרש מייל של הלקוח או חשבון מחובר.
  - **תקרות לכל נציג:** מקסימום הטבות בשיחה אחת, ומקסימום ללקוח (לפי חשבון) ב-30 יום; ומקסימום בקשות תשלום בשיחה. מעבר לתקרה הנציג מקבל הודעה, ואומר ללקוח בנימוס שהוא לא יכול.
  - כל פעולה נרשמת בשיחה ובטבלה `ai_actions`.
- כפתור **ניסוי** בטופס מאפשר לכתוב לו הודעה כמו לקוח ולראות מה הוא עונה, לפני שלקוחות פוגשים אותו.
- הוראות הנציג רואים רק מנהלים. ההגנה מפני לקוח שמנסה לשנות לו את ההוראות היא בקשה במודל, לא הבטחה: אל תכתבו בהוראות סיסמאות או מידע פנימי רגיש.

**שפה לכל נציג**
- בכל נציג (אנושי או AI) ובפרופיל האישי אפשר להגדיר את השפה שהוא כותב בה, פעם אחת. התרגום האוטומטי משתמש בה כשהנציג לוקח שיחה, ולא צריך לזהות אותה בכל שיחה מחדש (אין קריאה ל-Gemini לזיהוי). נציג בלי שפה מוגדרת מזוהה כמו קודם, מהתשובה הראשונה שלו.

**תרגום AI (Gemini)**
- כל הודעה של לקוח עוברת לזיהוי שפה (והשפה נשמרת בכרטיס הלקוח). התשובה הראשונה של הנציג מזהה את השפה שלו
- שפות שונות → הודעות הלקוח מתורגמות לנציג (עם המקור מתחת), ותשובות הנציג נשלחות ללקוח בשפה שלו (עם "הצגת המקור"). אותה שפה → אין תרגום ואין AI בשיחה
- תג 🌐 בראש השיחה מראה את המצב; נציג עם הרשאת "שליטה בתרגום" יכול להפעיל/לכבות ולבחור שפות ידנית

**התראות במייל**
| מתי | למי |
|---|---|
| שיחה חדשה כשאף נציג לא מחובר / הודעה מחוץ לשעות | הצוות (+ כתובות נוספות מההגדרות) |
| שיחה שלא נענתה אחרי X דקות | נציגים שלא מחוברים |
| הלקוח עזב לפני שראה את התשובה | הלקוח (אם השאיר מייל) |

## התקנה (פעם אחת, ~10 דקות, בלי טרמינל)

### 1. חיבור ה-Worker ל-GitHub (פריסה אוטומטית)
1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages → Create → Import a repository** → `rb077858/rb077858.github.io`.
2. **Root directory:** `support` · **Deploy command:** `npx wrangler deploy` · שם ה-Worker: `reem-chat`.
3. מעכשיו כל push ל-`main` שנוגע ב-`support/` נפרס אוטומטית. הדומיין `chat.reembir.com` מתחבר לבד (מוגדר ב-`wrangler.toml`).

> אין צורך ליצור מסד נתונים — הנתונים נשמרים ב-Durable Object עם SQLite מובנה (כלול בתוכנית החינמית).

### 2. משתנים סודיים
ב-Worker → **Settings → Variables and Secrets** → הוסיפו (סוג Secret):

| שם | ערך |
|---|---|
| `ADMIN_EMAILS` | המייל שלך. רק מייל שמופיע כאן יכול להקים את חשבון המנהל הראשון |
| `RESEND_API_KEY` | לא חובה: כשמוגדר `SSO_SERVICE_KEY`, המיילים יוצאים דרך חשבון Resend של login.reembir.com |

המיילים יוצאים מ-`support@reembir.com` (אפשר לשנות ב-`MAIL_FROM` ב-`wrangler.toml`).

**לא חובה — תשלומים ושדרוגים מתוך הצ׳אט:** בחרו סיסמה ארוכה ואקראית ושמרו אותה כסוד בשני ה-Workers:

| Worker | שם הסוד |
|---|---|
| `reem-chat` (הצ׳אט) | `SSO_SERVICE_KEY` |
| `reem-sso` (login.reembir.com) | `CHAT_SERVICE_KEY` — אותו ערך בדיוק |

שני ה-Workers מחוברים גם ב-Service Binding (מוגדר ב-`wrangler.toml` של כל אחד), כך שהם מדברים ישירות בלי לעבור באינטרנט.

**לא חובה — תרגום AI:** יוצרים מפתח ב-[Google AI Studio](https://aistudio.google.com/apikey) ומדביקים אותו ב-**הגדרות ← תרגום AI** (או כסוד `GEMINI_API_KEY`), ומפעילים את התרגום באותו מסך.

### 3. כניסה ראשונה
1. היכנסו ל-`https://chat.reembir.com/admin` → הכניסו את המייל מ-`ADMIN_EMAILS` → **שליחת קישור הגדרה**.
2. במייל: לחצו על הקישור ובחרו סיסמה — זהו, אתם מנהלים.
3. **צוות → הזמנת נציג/ה** כדי להוסיף עוד אנשים. (בלי Resend מוגדר, יוצג קישור הצטרפות שאפשר להעביר ידנית.)
4. **הגדרות → התקנה באתר** — השורה להדבקה, ו**דף הדגמה** לבדיקה.

## מבנה

| קובץ | מה יש בו |
|---|---|
| `src/index.js` | נקודת הכניסה: קבצים סטטיים, CORS, והעברת `/api` ו-`/ws` ל-Durable Object |
| `src/hub.js` | `ChatHub` — כל הלוגיקה: טבלאות, API, WebSockets, שיבוץ, התראות מתוזמנות (alarms), דוחות |
| `src/mail.js` | תבניות המיילים ושליחה דרך Resend |
| `src/util.js` | סיסמאות, טוקנים, עוגיות, זיהוי דפדפן |
| `src/ai.js` | זיהוי שפה ותרגום עם Gemini |
| `public/widget.js` | הווידג׳ט (קובץ אחד, בלי תלויות) |
| `public/admin/` | מוקד הנציגים (`admin.js` — תיבת השיחות, `tools.js` — תשלומים, שדרוגים, תרגום והרשאות, `pages.js` — שאר המסכים) |
| `public/demo/` | דף הדגמה |

**אבטחה:** סיסמאות ב-PBKDF2-SHA256 · עוגיית סשן HttpOnly + בדיקת Origin נגד CSRF (גם ב-WebSocket) · טוקנים נשמרים רק כ-hash · קישורי מייל חד-פעמיים עם תפוגה · הגבלת קצב · הערות Whisper לא נשלחות לדפדפן של הלקוח אף פעם · רשימת אתרים מורשים · קבצים מסוכנים (HTML/SVG/JS) נחסמים.

**מגבלות חינמיות:** Workers — 100K בקשות ביום · Durable Objects — 100K בקשות ביום (WebSockets במצב hibernation, כך שחיבור פתוח לא עולה כלום) · Resend — 100 מיילים ביום.
