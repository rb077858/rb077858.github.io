# שילוב פרויקט במערכת של reem.bi — הוראות לסוכן (Claude)

> **לבעלים:** בכל פרויקט חדש כותבים לסוכן:
> "לשילוב מערכת ההתחברות שלי באתר קרא: https://raw.githubusercontent.com/rb077858/rb077858.github.io/main/sso/INTEGRATE.md"

אתה מחבר פרויקט ל-**reem.bi** (login.reembir.com): מערכת אחת לכל הפרויקטים של הבעלים, שכוללת:
1. **התחברות** (SSO): חשבון אחד לכל האתרים.
2. **תוכניות והרשאות**: לכל אתר תוכניות עם JSON של הרשאות. הבעלים משדרג משתמשים מהדשבורד.
3. **תשלומים**: מנויים חודשיים וקודי קופון, הכול דרך חשבון PayPal **מרכזי אחד**. לאתר אין מפתחות PayPal משלו.
4. **מיילים**: כל המיילים של כל האתרים יוצאים דרך חשבון Resend **מרכזי אחד**. לאתר אין מפתח Resend משלו, ואת כתובת השולח בוחרים בדשבורד.
5. **ניהול**: כל הניהול של כל האתרים נמצא ב-login.reembir.com/admin. לאתר לא צריך להיות דף ניהול נפרד.

ענה לבעלים בעברית. הם לא מפתחים: תן הוראות ברורות, שלב אחרי שלב, בלי ז'רגון.

## 1. התחברות

```html
<script src="https://login.reembir.com/sdk.js"></script>
<script>
  const auth = ReemAuth.init({ clientId: 'CLIENT_ID' });

  auth.onChange(user => {
    // undefined = עדיין טוען (אל תציג "לא מחובר" בינתיים) · null = לא מחובר
    // user = { id, email, name, avatar, plan: { id, name } | null, features: { ... },
    //          access: { status, plan, plan_expires_at, features, subscription } }
  });

  loginBtn.onclick = () => auth.login();      // מפנה ל-login.reembir.com וחוזר לאותו דף מחובר
  logoutBtn.onclick = () => auth.logout();
</script>
```

| חבר | מה הוא עושה |
|---|---|
| `auth.login({ returnTo })` | התחברות. אחרי ההתחברות חוזרים ל-`returnTo` (ברירת מחדל: הדף הנוכחי) |
| `auth.logout()` | התנתקות |
| `auth.user` | `undefined` בטעינה, `null` לא מחובר, או אובייקט המשתמש |
| `auth.ready` | Promise שמתממש כשידוע אם יש משתמש |
| `auth.refresh()` | טוען מחדש משתמש ותוכנית |
| `auth.getToken()` | ה-Bearer token לשרת משלך |
| `auth.accountUrl()` | קישור לדף החשבון |
| `auth.getFirebaseToken()` | טוקן ל-`signInWithCustomToken` (פרויקטים עם Firebase) |
| `auth.billing.*` | תשלומים, ראה סעיף 4 |

**כללים**
- הסקריפט נטען **לפני** הקוד שמשתמש ב-`ReemAuth`, ו-`init` נקרא **פעם אחת** בכל דף.
- **אם `window.ReemAuth` לא קיים** (השרת לא זמין), האתר ממשיך לעבוד: כפתור ההתחברות מושבת עם הודעה קטנה.
- **ממשק:**
  - כפתור "התחברות".
  - כשמחוברים: שם או תמונה, קישור "החשבון שלי" (`auth.accountUrl()`) ו"התנתקות".
  - מתאים לעיצוב, ונראה טוב בנייד בלי גלילה לצדדים.
- **טקסט מהמשתמש** (שם, מייל) מוצג תמיד עם `textContent`, לא ב-`innerHTML`.
- **לא כותבים OAuth בעצמך, ולא שומרים טוקנים במקום אחר.** הספרייה מטפלת בהכול (PKCE, localStorage, ניקוי הכתובת).
- **הקשר מאובטח:** נדרש https, או localhost בבדיקות.

### שרת משלו
אל תסמוך על מה שהדפדפן אומר. הדפדפן שולח `Authorization: Bearer <auth.getToken()>`, והשרת בודק:
```js
const res = await fetch('https://login.reembir.com/api/userinfo', { headers: { Authorization: request.headers.get('Authorization') } });
if (!res.ok) return new Response('לא מחובר', { status: 401 });   // 401/403 = לא מחובר או אין גישה
const { user, access } = await res.json();   // user.email (אותיות קטנות), access.plan, access.features, access.subscription
```
אפשר לשמור את התשובה במטמון לדקה לפי הטוקן. תוסיף אפשרות לעקוף את המטמון (למשל `?fresh=1`) לבקשה הראשונה אחרי תשלום.

### Firebase
1. **בדפדפן:** אחרי ההתחברות, `signInWithCustomToken(getAuth(app), await auth.getFirebaseToken())`, ובהתנתקות גם `signOut`.
2. **מזהים בחוקי Firestore:**
   - ה-uid הוא `user.id`.
   - בחוקים זמינים `request.auth.token.sso_email`, `sso_site` ו-`sso_plan`.
3. **אם `getFirebaseToken` זורק `not_configured`:** תמשיך בלי, ותכתוב לבעלים שצריך את הסוד `FIREBASE_SA_<ID>` ב-Worker **reem-sso**.
4. **חוקים:** תכין `firestore.rules` מוצע, אבל אל תפרסם אותו בעצמך.

## 2. תוכניות והרשאות

התוכניות מוגדרות בדשבורד (אתרים ← האתר ← **תוכניות ומחירים**). המזהים הם בצורה `CLIENT_ID:key`, למשל `my-app:pro`. לכל תוכנית יש JSON של הרשאות **שאתה ממציא** לפי מה שהפרויקט צריך, והקוד שלך קורא אותו:
```js
const limit = user.features.limit ?? 10;          // תמיד עם ברירת מחדל סבירה
if (user.features.export) { /* פיצ'ר של Pro */ }
```
- **`user.features`** = ה-JSON של התוכנית + הרשאות אישיות שהבעלים נתן למשתמש מסוים.
- **מוסכמה:** `-1` = ללא הגבלה. אם יש מכסה, תתמוך גם ב-`{"unlimited": true}`.
- **מגבלות חובה בשרת:** אם לפרויקט יש שרת, מגבלות שעולות כסף נבדקות בשרת, לא רק בדפדפן.
- **תכתוב לבעלים** אילו תוכניות ליצור ואיזה JSON לכל אחת (סעיף 6).

## 4. תשלומים (מנויים חודשיים)

**אסור** להוסיף לאתר מפתחות PayPal משלו. **אם יש כאלה, תסיר אותם.** הכול עובר דרך `auth.billing`, וה-PayPal המרכזי של reem.bi.

```js
const { plans, free, paypal } = await auth.billing.catalog();
// plans = [{ id, name, description, price, currency, features, paypal_plan_id }]  — רק תוכניות עם מחיר שמוצגות
// free  = תוכנית ברירת המחדל של האתר (אם יש) · paypal = null אם התשלומים עוד לא הופעלו

// כפתור הרשמה (PayPal: חשבון או כרטיס אשראי). דורש משתמש מחובר
auth.billing.button(container, plan.paypal_plan_id, {
  onSuccess: user => { /* המנוי הופעל: user.plan כבר מעודכן. אם יש שרת — לבקש ממנו מידע מחדש (fresh) */ },
  onError: err => { /* להציג הודעה */ },
});

// המצב הנוכחי
user.access.subscription   // { status: 'ACTIVE' | 'CANCELLED', plan_id, paid_until (שניות) } או null
await auth.billing.cancel();                       // ביטול. ממשיך לעבוד עד סוף החודש ששולם

// קודי קופון
const c = await auth.billing.checkCoupon(code);    // זורק Error עם הודעה בעברית אם הקוד לא תקף
// c.type: 'percent' | 'amount' | 'trial' | 'gift' · c.label: תיאור בעברית
// הנחה: c.offers[planId] = { first_price, months, regular_price, paypal_plan_id } — להציג מחיר מוזל ולהשתמש ב-paypal_plan_id הזה בכפתור
// מתנה: c.plan_id — כפתור "הפעלת המתנה" שקורא ל:
await auth.billing.redeem(code);
```

**מה לבנות:**
1. **כרטיסי מחירים מתוך `catalog()`.** לא מחירים קבועים בקוד, כי הבעלים משנה מחירים בדשבורד.
   - תוכנית חינם, אם יש.
   - כל תוכנית: מחיר לחודש ומה היא נותנת (מתוך `features`).
   - "התוכנית הנוכחית שלך" על התוכנית של המשתמש.
   - משתמש לא מחובר: "התחברות להרשמה".
   - משתמש עם מנוי שמשדרג: "המנוי הנוכחי יבוטל אוטומטית".
2. **שדה "יש לך קוד קופון?"** מעל הכרטיסים.
   - **תמיכה ב-`?coupon=CODE` בכתובת:** הדשבורד יוצר קישורים כאלה.
   - **משתמש לא מחובר:** שומרים את הקוד ב-sessionStorage, מחברים אותו, ומחילים את הקוד אחרי החזרה.
3. **"ביטול מנוי"** כשיש `subscription.status === 'ACTIVE'`.
4. **אם `paypal === null`:** "ההרשמה תיפתח בקרוב" במקום כפתור.

## 4א. מיילים

**אסור** להוסיף לאתר מפתח Resend (או ספק מיילים אחר). **אם יש, תסיר אותו.** reem.bi שולח בשם האתר, מכתובת השולח שהבעלים בחר: אתרים ← האתר ← הגדרות ← **שליחת מיילים**. כל דומיין שמאומת בחשבון Resend שלו זמין שם.

```js
// למשתמש המחובר בלבד (למשל "שלח לי את הקובץ"). עובד מהדפדפן וגם מהשרת. עד 30 ביום למשתמש
await auth.emailMe({
  subject: 'הקובץ שלך',
  text: 'מצורף',                        // או html
  attachments: [{ filename: 'file.txt', content: base64 }],
});
// מהשרת: אותה בקשה ל-POST https://login.reembir.com/api/email/me עם Authorization: Bearer <הטוקן של המשתמש>
```

```js
// משרת האתר לכל נמען (התראות, הזמנות). דורש מפתח שרת של האתר (הגדרות ← מפתח שרת ← SSO_SITE_KEY). עד 50 נמענים בבקשה, 500 ביום לאתר
await fetch('https://login.reembir.com/api/site/email', {
  method: 'POST',
  headers: { 'x-site-key': env.SSO_SITE_KEY, 'Content-Type': 'application/json' },
  body: JSON.stringify({ to: ['a@b.com'], subject: '…', html: '…', text: '…', reply_to: 'support@reembir.com' }),
});
```
- **מיילים שעולים כסף או נשלחים לפי פעולה של משתמש:** מגבלות בשרת של האתר, למשל רק לתוכניות בתשלום.
- **ברירת מחדל:** אם הבעלים לא בחר כתובת, המייל יוצא מכתובת ברירת המחדל של reem.bi. תכתוב לו איזו כתובת לבחור.

## 5. ניהול: הכול בדשבורד המרכזי

לבעלים יש דשבורד אחד: login.reembir.com/admin ← **אתרים** ← האתר. ממנו הוא כבר מנהל משתמשים, תוכניות, מחירים, קופונים ומנויים. **אל תבנה לאתר מסכים של אלה.** מה שספציפי לאתר מתחבר לדשבורד באחת משתי דרכים:

### א. לאתר יש שרת: מניפסט (מומלץ)
הדשבורד מציג בדף של האתר נתונים, בדיקות ופעולות שהשרת מתאר. הדשבורד קורא לשרת מהדפדפן עם טוקן קצר של המנהל. הכתובות יחסיות ל**כתובת האתר** שבהגדרות:
1. **אימות:** `GET <site url>api/admin/manifest`. בודקים את הטוקן מול `/api/userinfo` כרגיל, ומנהל הוא מי שהמייל שלו ב-`ADMIN_EMAILS` של האתר. אחרת 403.
2. **CORS ל-`https://login.reembir.com`** בנתיבים `/api/admin/*`: `OPTIONS` עם `Access-Control-Allow-Origin`, `Allow-Headers: Authorization, Content-Type`, `Allow-Methods: GET, POST, DELETE, OPTIONS`.
3. **התשובה (כל חלק לא חובה):**
```js
{
  version: 1,
  stats:   [{ label: 'השתמשו החודש', value: 42 }],
  checks:  [{ label: 'OPENAI_API_KEY', ok: true, detail: 'מוגדר' }],              // מה חסר בהגדרות
  actions: [{ id: 'rebuild', label: 'בנייה מחדש', description: '…', confirm: 'בטוח?', primary: false }],
           // לחיצה = POST <site url>api/admin/actions/<id> → { message }
  lists:   [{ title: 'פעילות אחרונה', empty: 'אין', items: [{ title, subtitle, date /* ms */, dateLabel, badge, badgeLevel: 'green'|'red'|'' }] }],
}
```
**דוגמה מלאה:** `adminManifest` ב-`src/index.js` של `rb077858/timlul`.

### ב. לאתר יש דף ניהול בדפדפן (בלי שרת, למשל Firebase): הטמעה
הדשבורד מציג את הדף בלשונית **"ניהול האתר"** של האתר, **מחובר אוטומטית**: `sdk.js` מזהה שהוא בתוך הדשבורד ומקבל ממנו טוקן, בלי הפניה. צריך:
1. **דף שלם ונוח בנייד:** הדף עובד גם כשהוא ממוסגר בגובה מלא.
2. **אין `X-Frame-Options: DENY`.** אם יש CSP, `frame-ancestors 'self' https://login.reembir.com`.
3. **ההתחברות בדף רק דרך `sdk.js`.** אם הדף פותח לוגין משלו (סיסמה, Google), תחליף.
4. **לבעלים:** לרשום את הכתובת (למשל `https://reembir.com/X/admin/`) בהגדרות האתר ← **כתובת ממשק הניהול**.

### מעבר מדף ניהול קיים
1. **מה הדשבורד כבר עושה:** משתמשים, הרשאות, תוכניות, מחירים, קופונים, מנויים ותשלומים. מה שהדף הקיים עשה מתוך אלה, תוריד ממנו.
2. **מה שספציפי לאתר:** סטטיסטיקות ופעולות יעברו למניפסט (א). מסכים מורכבים יוטמעו (ב).
3. **ניקוי:** תסיר קישורים, כתובות ומסמכים שמפנים לדף הישן. הקישור "ניהול" באתר יפנה ל-`https://login.reembir.com/admin#sites/CLIENT_ID`.

## 6. בדיקה ומה להגיד לבעלים בסוף

**תבדוק:**
1. **שרת מקומי:** אם יש לך דפדפן, תריץ ותוודא שאין שגיאות ושזה נראה טוב בנייד.
2. **בדיקות אוטומטיות:** אם יש לפרויקט שרת, תכתוב בדיקות עם `/api/userinfo` מדומה.

**תכתוב לבעלים, בעברית ובצעדים ממוספרים:**
1. **מה לרשום בדשבורד** (login.reembir.com/admin ← אתרים ← **+ אתר חדש**):
   - מזהה, שם, כתובת האתר ותיאור.
   - **כתובות חזרה מותרות:** כל הכתובות שבהן האתר נגיש, עם `/` בסוף, ו-`http://localhost:<port>/` אם בדקת מקומית.
   - **מי יכול להיכנס:** פתוח / באישור / בהזמנה. תמליץ לפי אופי הפרויקט.
   - **כתובת ממשק הניהול:** אם יש (סעיף 5ב).
2. **אילו תוכניות ליצור** בלשונית **תוכניות ומחירים**:
   - מזהה, שם, JSON מוכן לכל אחת, ומחיר חודשי אם היא נמכרת.
   - איזו תוכנית לבחור ל"משתמשים חדשים".
3. **כתובת שולח:** אם האתר שולח מיילים, איזו כתובת לבחור ב**הגדרות** ← **שליחת מיילים** (למשל `שם האתר <my-app@reembir.com>`).
4. **סודות:** אם צריך סוד ב-Cloudflare, איך קוראים לו ומאיפה מביאים אותו. למשל `ADMIN_EMAILS` לאתר עם שרת, `SSO_SITE_KEY` לשליחה משרת לנמענים אחרים, או `FIREBASE_SA_<ID>` ב-reem-sso.
5. **מה שונה:** מה השתנה, ומה הוסר (התחברות ישנה, מפתחות PayPal או Resend ישנים, דף ניהול ישן) ואם צריך למחוק משהו בצד שלו.
6. **בדיקה:** איך לבדוק שזה עובד.
7. **commit ו-PR:** תעשה commit ותפתח PR. תמזג רק אם הבעלים ביקש.

**אל תעשה:**
- אל תבקש סיסמאות או מפתחות בשיחה.
- אל תשנה דברים שלא קשורים.
- אל תשאיר תשלומים או שליחת מיילים שעוקפים את המערכת המרכזית.
