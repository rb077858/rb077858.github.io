## איך המערכת עובדת (כדי שתבין מה אתה משלב)
- הספרייה נטענת מ-`https://login.reembir.com/sdk.js` ומגדירה את `window.ReemAuth`.
- `auth.login()` מפנה ל-login.reembir.com. שם המשתמש מתחבר (סיסמה / Google / קישור במייל) וחוזר לאותו דף עם `?code=…&state=…`. הספרייה מחליפה את הקוד בטוקן בעצמה (Authorization Code + PKCE), שומרת אותו ב-localStorage (`reemauth:<clientId>`) ומנקה את הכתובת. **לא צריך לכתוב שום קוד OAuth.**
- כתובת החזרה (redirect URI) היא כברירת מחדל `location.origin + location.pathname` של הדף שבו קראו ל-`init`. היא חייבת להיות מאושרת בדשבורד (התאמת prefix; כתובת שמסתיימת ב-`/` מכסה את כל מה שמתחתיה).
- התוכנית וההרשאות של המשתמש (למשל `{"limit": 50}`) מוגדרות בדשבורד לכל אתר, ומגיעות ב-`user.plan` וב-`user.features`.
- נדרש הקשר מאובטח (https או localhost), כי הספרייה משתמשת ב-`crypto.subtle`.

## ה-API של הספרייה

```html
<script src="https://login.reembir.com/sdk.js"></script>
<script>
  const auth = ReemAuth.init({ clientId: 'CLIENT_ID' });
  // אופציונלי: ReemAuth.init({ clientId, redirectUri: 'https://…/' })  — אם צריך כתובת חזרה קבועה

  auth.onChange(user => {
    // נקרא מיד אם המצב ידוע, ובכל שינוי (התחברות / התנתקות / רענון)
    // user === null  → לא מחובר
    // user = {
    //   id, email, name, avatar,
    //   plan: { id: 'CLIENT_ID:pro', name: 'Pro' } | null,
    //   features: { ... },          // ההרשאות מהתוכנית + הרשאות אישיות מהדשבורד
    //   access: { status, plan, plan_expires_at, plan_expired, features }
    // }
  });
</script>
```

| חבר | מה הוא עושה |
|---|---|
| `auth.login(opts?)` | מפנה להתחברות. `opts.returnTo` = כתובת לחזור אליה (למשל עם `#section`). `opts.prompt = 'select_account'` = תמיד להציג בחירת חשבון |
| `auth.logout()` | מתנתק מהאתר הזה (מחזיר Promise) |
| `auth.user` | `undefined` בזמן טעינה, `null` לא מחובר, או אובייקט המשתמש |
| `auth.ready` | Promise שמתממש כשידוע אם יש משתמש |
| `auth.error` | אחרי חזרה מהתחברות שנכשלה, למשל `'no_access'` (אין לו גישה לאתר) |
| `auth.refresh()` | טוען מחדש משתמש ותוכנית מהשרת |
| `auth.getToken()` | ה-Bearer token של האתר (לשרת משלך) |
| `auth.api(path, { method, body })` | קריאה ל-`https://login.reembir.com` + path עם הטוקן. מחזיר JSON או זורק `Error` עם `.code` ו-`.status` |
| `auth.getFirebaseToken()` | Promise לטוקן עבור `signInWithCustomToken` של Firebase |
| `auth.accountUrl()` | קישור לדף החשבון של המשתמש |

## הנחיות לשילוב

**בסיס**
- הוסף `<script src="https://login.reembir.com/sdk.js"></script>` **לפני** הקוד שמשתמש ב-`ReemAuth`, בכל דף שצריך התחברות.
- קרא ל-`ReemAuth.init` **פעם אחת** בכל דף, עם ה-client_id המדויק.
- אם `window.ReemAuth` לא קיים (השרת לא זמין), האתר חייב להמשיך לעבוד. תשבית את כפתור ההתחברות ותציג הודעה קטנה, בלי לקרוס.
- טפל במצב הטעינה (`auth.user === undefined`) כדי שלא יהבהב ממשק של "לא מחובר".

**ממשק**
- כפתור "התחברות" (בעברית, או "Sign in" אם האתר באנגלית).
- כשמחוברים: שם או תמונה של המשתמש, קישור ל"החשבון שלי" (`auth.accountUrl()`) וכפתור "התנתקות".
- התאם לעיצוב, לשפה ולכיוון (RTL/LTR) של האתר, ותוודא שזה נראה טוב בנייד (בלי גלילה לצדדים).
- כל טקסט שמגיע מהמשתמש (שם, מייל) מוצג עם `textContent` או escaping, לעולם לא ישירות ב-`innerHTML`.

**מה נפתח רק למחוברים**
- תבין מהמאגר מה צריך להיות רק למחוברים, ותחסום רק את זה.
- אם יש מגבלות כמו כמות פריטים או פיצ'רים לפרימיום, תקרא אותן מ-`user.features` עם ברירת מחדל סבירה כשהשדה חסר. תכתוב לי אילו שמות שדות בחרת, כדי שאגדיר אותם בתוכניות בדשבורד.

**החלפת התחברות קיימת**
- אם יש התחברות קיימת (למשל Firebase Auth עם Google), תחליף אותה ב-reem.bi.
- הנתונים הקיימים חייבים להמשיך לעבוד. אם הם מקושרים למייל, `user.email` הוא אותו מייל (באותיות קטנות).

**Firebase**
- אם הפרויקט שומר נתונים ב-Firebase/Firestore: אחרי שהמשתמש מחובר תבצע `signInWithCustomToken(getAuth(app), await auth.getFirebaseToken())`, ובהתנתקות גם `signOut` של Firebase.
- ה-uid ב-Firebase יהיה `user.id`. המייל זמין בחוקי Firestore כ-`request.auth.token.sso_email`, ויש גם `sso_site` ו-`sso_plan`.
- אם `getFirebaseToken` זורק שגיאה עם `code === 'not_configured'`, תמשיך בלי (ותכתוב לי שצריך להגדיר סוד).
- תכין קובץ `firestore.rules` מוצע שמבוסס על `sso_email`, אבל אל תפרסם אותו בעצמך.

**שרת משלו**
- אם לפרויקט יש שרת, הדפדפן שולח `Authorization: Bearer <auth.getToken()>`.
- השרת מאמת עם `GET https://login.reembir.com/api/userinfo` ואותו header. תשובה 200 מחזירה `{ user, access }`. תשובה 401 או 403 = לא מחובר או אין גישה.
- לעולם אל תסמוך על פרטי משתמש שהדפדפן שולח בלי האימות הזה.

**אל תעשה**
- אל תכתוב OAuth בעצמך, ואל תשמור טוקנים במקום אחר.
- אל תבקש ממני סיסמאות או מפתחות.
- אל תשנה דברים שלא קשורים להתחברות.
